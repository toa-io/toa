# Migrating from 1.0.0-alpha.292

What only some applications use is no longer installed for all of them. An image carries what its
components declare, and a workspace installs the same set itself.

## A storage provider's SDK is installed by the application

`@toa.io/extensions.storages` no longer depends on `@aws-sdk/client-s3`, `@aws-sdk/lib-storage` or
`cloudinary`. A deploy installs what the components of each composition declare — the storages
their manifests name, on the providers the context annotates them with — so an image carries the
SDK of a provider it uses and no other. `fs`, `tmp` and `test` need nothing.

A workspace has no composition, so it installs the set itself. Where it has not, a composition
fails to start:

```
Storage provider 'cloudinary' needs cloudinary@2.11.0, which is not installed.
```

## A component the exposition ships declares what it imports

`@node-rs/bcrypt`, `@simplewebauthn/server`, `lru-cache`, `paseto` and `jose` belong to
`identity.basic`, `identity.passkeys`, `identity.tokens` and `identity.federation`, not to
`@toa.io/extensions.exposition`. The image that runs those components installs them; an
application that runs none of them carries none of them, and neither does the runtime image.

Composing locally, the workspace installs them as it does a storage provider's SDK.

## `toa npm` installs both

```shell
$ toa npm -p application
```

reads the Context, collects what its components declare and what the services bring, and installs
into the nearest `package.json` above it whatever that manifest does not already declare. `-n`
prints the list instead. Run it again when a storage or a component is added.

## `toa export manifest` takes no `--jsonpath`

The flag selected one value out of a manifest with a JSONPath expression, and cost 5.1 MB —
`jsonpath` with `underscore`, `esprima`, `escodegen` and `source-map` — in every image. Print the
manifest and select from it:

```shell
$ toa export manifest -o json | jq '.entity.properties.name'
```

## `toa key` needs the deployment library

`paseto` is an optional peer of `@toa.io/cli` and a dependency of `@toa.io/operations`. `toa key`
still generates a jwe key with it uninstalled; a paseto key and a key pair say what to add:

```
`toa key` needs @toa.io/operations, which is not installed
```

## `queues` is not a shortcut, and a manifest states no `properties`

A manifest that wrote `queues:` had it resolved to `@toa.io/storages.queues`, whose last publish
is `0.20.0-dev.31` and which no install could get. The `properties` key it landed in went with
it: nothing in the runtime, the bridges or the connectors has ever read one, so a manifest that
writes it is refused rather than carried.

## `toa compose` takes no `--bindings`, and there is no `toa limits`

The option said `OBSOLETE` in its own help and overrode every operation's binding at boot.
Declare `bindings` in the manifest.

`toa limits` printed `kubectl get pods` with a fixed set of columns and had nothing of Toa in
it. Run `kubectl` yourself.

## A prototype is in a package, or an image cannot carry it

A composition image now carries `manifest.toa.json` beside each component — the manifest as the
build normalised it — and the process reads it instead of normalising again. A prototype that is
a directory of the application's own rather than a package reference cannot be written there, and
the build says so:

```
'<path>' is in no package, so an image cannot carry what is in it
```

Such a prototype never worked in an image, since nothing between the components is copied into
one; the failure has moved from the container to the build. Put a shared prototype in a package
and name it by its reference.

## A custom base image installs the runtime in `/toa`

`registry.build.run` that installs `@toa.io/runtime` elsewhere is no longer enough: what an
extension needs for what a component declares is installed beside the extension, in `/toa`.

## What to do

1. Run `toa npm` where the application is developed, and add it beside `npm i` in its setup.
2. Replace `toa export manifest --jsonpath <expression>` with `-o json` and a selector of your
   own, and have `@toa.io/operations` in `devDependencies` where `toa key --format paseto` or
   `toa key --public` runs.
3. Where `registry.build.image` names a base of your own, install the runtime into `/toa`.
4. Replace `queues:`, `properties:` and `toa compose --bindings` with what the manifest
   declares, and `toa limits` with `kubectl`.
5. Name a shared prototype by the package that holds it.
