# Migrating from 1.0.0-alpha.299

## A call no longer writes the runtime's own fields onto the request it is given

An operation that hands `context.local` or `context.remote` a request used to get that object back
with `authentic`, `telemetry` and `trail` on it, and with `input` defaulted to `null` where it had
none. It no longer does: the call builds its own envelope around what it was given, and only that
envelope is sent.

```javascript
const request = { input: { size: '42' } }

await context.remote.store.orders.place(request)

request.authentic // was true; is undefined
request.telemetry // was a traceparent; is undefined
```

None of those was ever declared, and nothing is meant to read a request back after a call — but
code that did will see the difference. Read what the call answered instead.

What has not changed: `source` is still stamped on the object, by the bridge rather than the call,
and what the request schema coerces inside `input` and `query` still lands on the objects you
passed.

This is what lets a call carry an identity at all. One request object is handed to several
concurrent calls in more than one place, and an identity written onto it would make every call
after the first read as a duplicate of the first.
