# Migrating from 1.0.0-alpha.298

A record carries the region that wrote it, so that deployments of one context in several places
can be told apart. Everything below happens whether or not an application ever has more than one.

## `REGION` is a system property

Beside `id`, `VERSION`, `CREATED`, `UPDATED` and `DELETED`, a record now holds `REGION`: which
region wrote it, as the rank that region was declared with. A component that declares one of its
own no longer builds:

```
System property 'REGION' cannot be overridden
```

Rename the property. It may not be named in `blank` either.

An application deployed in one place has one region, so every record holds `0` and nothing reads
it.

A migration gives that value to the records written before this version, once per database, when
it first starts on this one. What reads `REGION` tolerates its absence as well, so nothing depends
on the migration having run — but a record that lacks it would beat every equal-version write from
anywhere, so it is written rather than left out.

## The region an existing application is deployed as is rank 0

Where a context comes to declare several regions, the one an existing deployment becomes is
declared first, at rank `0`. Its records were written by that region, and that is what the
migration records them as.
