# Migrating from 1.0.0-alpha.314

## A deployed map is gzipped

The ConfigMap a deployment mounts holds the component map compressed, as `/etc/toa/.map.json.gz`,
which is what the image's command names. Anything that reads that path by hand — a debug script, a
sidecar, a readiness check — reads the new name and decompresses it:

```shell
$ kubectl exec <pod> -- zcat /etc/toa/.map.json.gz
```

A map given to a process any other way is unchanged: `--map` names whatever file it is given, and a
process reads a plain one and a gzipped one alike.

## A map says less, and means the same

`toa map` no longer writes what the runtime gives every component — an entity's system properties
and their place in `required`, an operation's binding where it is the component's, an `output` that
describes nothing, and a `query` that follows from the scope. The process that reads the map puts
them back, so what a caller is held to and what a route publishes are unchanged.

Nothing to do, unless something of yours reads `.map.json` itself. The file is generated and is
meant to be in `.gitignore`; where one is read all the same, read it as
[contracts](/documentation/contracts.md#the-map) describes it. A map written by an earlier release
is still read by this one.

## What to do

1. Read a deployed map at `/etc/toa/.map.json.gz`, through `zcat`, where anything reads one.
2. Run `toa map` again wherever a map is written by hand, so what is deployed and what is read are
   written by one release.
