# Migrating from 1.0.0-alpha.286

The system timestamps, and every property declared as a moment, are stored as dates. A system
property is the runtime's to declare.

**This release requires downtime**: a record written before it holds a number where this one
reads a date, and the first replica to start converts the collection — see
[285](285.md#the-old-and-the-new-version-must-not-run-at-once) for the shape of it.

## A moment is stored as a date

`CREATED`, `UPDATED` and `DELETED`, and a property of yours declared with `format: epoch-millis`
or `format: date-time`, are held in MongoDB as dates. What an operation reads and writes is what
the property declares — milliseconds or an ISO string — and nothing in userland changes.

A record written before this holds a number: a criterion by time does not match it, a sort
puts it ahead of every date, and a `ttl` index skips it. The runtime converts the system
timestamps at start, once per collection, before the component serves; stop every replica of
the release before this one first. A property of yours that takes the format now is converted by
a migration of the component, see
[Migrations](/documentation/component/declaration.md#migrations).

## A system property is the runtime's to declare

`VERSION`, `CREATED`, `UPDATED` and `DELETED` come from the prototype every stored component takes.
A manifest that declares one of them in `entity.properties` is refused:

```
System property 'DELETED' cannot be overridden
```

`id` may still be declared, by a component that owns its identifiers.

## What to do

1. Drop `VERSION`, `CREATED`, `UPDATED` and `DELETED` from every `entity.properties` of yours.
2. Stop every replica of the release before this one, upgrade, and start.
