# Migrating from 1.0.0-alpha.329

## A browser request to the gateway is sent without credentials mode

The gateway answers CORS with wildcards: `access-control-allow-origin: *`, and no
`access-control-allow-credentials`. A browser refuses such a reply for a request sent in
credentials mode, and the page sees a failed request:

```js
fetch(url, { credentials: 'include', headers: { authorization } }) // refused by the browser
fetch(url, { headers: { authorization } }) // as before
```

The gateway sets no cookies, so that mode carried nothing. A request made by a page of the same
origin, or outside a browser, is not affected.

1. Remove `credentials: 'include'` from `fetch`, and `withCredentials` from `XMLHttpRequest` and
   `EventSource`, wherever the gateway is called from another origin.
2. Upgrade `@toa.io/origin` to the release that carries
   [toa-io/origin#6](https://github.com/toa-io/origin/pull/6): before it, a request that states
   its own `authorization` beside `credentials: 'include'` is sent in that mode.
3. Stop relying on `vary: origin` and on a reply that names the origin it answers: neither is
   sent.
