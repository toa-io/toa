# Migrating from 1.0.0-alpha.307

## A component is given what another one provides, rather than asking for it

Nothing is looked up over the broker. `toa map` writes the contract of every component of a Context
beside its version, and a process reads what it was given: `.lookup`, the queue behind it, and the
wait with no deadline are gone.

What this means for what you run:

- **The map file is named `.map.json`**, where it was `components.json`. Whatever writes one —
  an `env` script, a process supervisor, an image entrypoint — writes the new name, and a `--map`
  that names the old one still works, because it is named rather than found. Move it in
  `.gitignore` too.
- **`toa call` reads a map**, and is refused where a Context is there and its map is not, as
  `compose`, `serve` and `mono` already are.
- **A process that calls a component it neither composes nor finds in its map is refused**, naming
  the component and `toa map`, where before it asked whichever replica answered. A component run
  outside a Context in a container of its own — one an application starts itself — is given the map
  the way it is given the environment.

```shell
$ toa map -p application
$ toa compose ./application/components/* --env application/.env --map application/.map.json
```

**Upgrade the whole Context at once.** A process of this release calls a component of an earlier one
without asking it anything, and a component of an earlier release asks `.lookup` of a peer of this
one and is not answered. A [halt](/documentation/halt.md) is the window for it: nothing serves while
the deployment is down, so the two releases never serve beside each other.

## A composition says what it composes, and what the map says has to agree

A composition whose component's version differs from what the map states for it is refused at boot,
naming the component. A deployment cannot hit this — one `toa deploy` writes both — and a local run
that forgot to re-run `toa map` is told so instead of calling its peers with a contract that is not
what they are running.

## A version is made of what a build ships

What no build ships is out of the hash a version is: `node_modules`, lockfiles, tests, type
declarations, `Dockerfile`s, tool and editor output. **Every version changes with this release**,
so every image is built again by the next deploy.

A component built somewhere else — one an application builds with a `.dockerignore` of its own —
says what its version is made of, so that both builds agree:

```yaml
# manifest.toa.yaml
files: [operations, events, receivers, lib, rc, package.json]
ignore: ['lib/fixtures/**', '!Dockerfile']
```

## An `expires` policy over the lookup queues has nothing left to clear

Every `<namespace>.<name>..lookup` queue is left with no consumer and no publisher by this release.
Nothing declares them again, so whatever policy was set over them can go with them.
