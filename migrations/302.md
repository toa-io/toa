# Migrating from 1.0.0-alpha.302

## An entity's properties come in the order its record holds them

A record read from a storage answers its properties in the order it holds them, and `id` comes
after them rather than first. Where a reply was compared as text, compare it as a value, or write
the properties in the order the record holds them.

```yaml
# a list of entities, as it was compared
- id: 4c4759e6f9c74da989d64511df42d6f4
  title: First pot

# and as it reads now
- title: First pot
  id: 4c4759e6f9c74da989d64511df42d6f4
```

## An agent matches a reply's lines wherever they stand

`responseIncludes` of `@toa.io/agent` asserts that the reply holds every line given to it,
wherever each one stands in it. `responseIncludesInOrder` asserts the order as well, which is what
`responseIncludes` did.

```javascript
// a reply whose order is what the suite asserts
agent.responseIncludesInOrder(expected)
```

## A Method's projection is read

The `projection` of a Method's query states what its Observation reads, where before it was
accepted and left unread. A Method that declares one for an operation of any other type does not
start, and neither does one whose projection names `id`, which is always read.

```yaml
/pots:
  GET:
    endpoint: enumerate
    query:
      projection: [title, volume]
```

## A reply is restricted where the operation answered it

What `io:output` admits is what the request asks the operation for, and the operation answers that
much of its output. A Method that declares no `io:output`, or declares `false`, asks for nothing,
so its reply has no body and takes the status an absent body takes: `204`, `201` to `POST`, and
`404` where the operation found nothing, where it was `200` with an empty body.

An operation that answers a value that is not an object — a string, a number — answers it as it is,
where such a reply was dropped with a warning; and a Method whose `io:status` or `auth:incept`
names a property lists that property in its `io:output`, since what the operation answers is what
they read.

## A reply is validated by its body, and `last-modified` is gone

`etag` on a safe request is a hash of the body the client receives, where it was the entity's
`VERSION` in quotes. A conditional `GET` works as it did: send back what `etag` stated, and a
reply the client already holds is answered `304`. A reply stating `no-store` carries no tag,
since a client that may not keep it never sends one back.

`last-modified` is no longer sent, and a reply no longer carries `UPDATED` or `CREATED` for it.

`if-match` is unchanged — it carries the `VERSION` a client read in the body, which is what an
operation refuses a stale write by — so a Method whose clients use optimistic concurrency lists
`VERSION` in its `io:output`.

1. Compare a reply as a value, or list an entity's properties in the order its record holds them,
   with `id` last.
2. Where a suite asserts the order of a reply, call `responseIncludesInOrder` in place of
   `responseIncludes`.
3. Take `projection` off a Method that is not mapped to an Observation, and take `id` out of one
   that names it. Where a Method declares one, its operation receives what the projection names,
   `id` and the system properties, and nothing else.
4. List in `io:output` the property `io:status` or `auth:incept` reads, and expect `204` where a
   Method sends no output.
5. Read `etag` from the reply rather than building it out of `VERSION`, and stop reading
   `last-modified`; list `VERSION` in `io:output` where clients send `if-match`.
