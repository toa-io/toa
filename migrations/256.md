# Migrating from 1.0.0-alpha.256

## A federated credential holds its Identity

Up to this release, a credential of `identity.federation` is stored under the id of the Identity
it stands for, and a credential asserted on authentication holds no `identity` of its own. From
1.0.0-alpha.257 a credential has an id of its own, its Identity is read from `identity` alone, and
an Identity has one credential per issuer.

A release from 1.0.0-alpha.257 through 1.0.0-alpha.323, over a database this one wrote:

- answers a credential without `identity` as no Identity, so authenticating with it fails;
- does not start the service that hosts `identity.federation` — the gateway — where two such
  credentials share an issuer under one authority:

  ```
  E11000 duplicate key error collection: <database>.identity_federation index: unique_identity dup key: { authority: "<authority>", iss: "<issuer>", identity: null }
  ```

A later release gives each such credential its Identity as it starts, before it makes that index,
by the component's own migration, `0001-identity`. It does the same for a database a release from
1.0.0-alpha.257 has started on already.

This release goes on writing credentials without `identity` after the migration has run, so the
gateway of this release stops before the one of the next is deployed.

Upgrading to a release from 1.0.0-alpha.257 through 1.0.0-alpha.323 instead, the same change is
applied by hand to the context's database, once the gateway of this release has stopped and before
the next one starts:

```js
db.identity_federation.updateMany(
  { identity: { $exists: false } },
  [{ $set: { identity: '$_id' } }]
)
```

A gateway that has failed to start on the index takes up to half a minute to start once the
records are fixed, waiting out the migration the failed start left unfinished.

## What to do

1. Stop the gateway before deploying the next release.
2. Upgrading to a release later than 1.0.0-alpha.323, nothing else.
3. Upgrading to a release from 1.0.0-alpha.257 through 1.0.0-alpha.323, run the update above
   before it starts.
