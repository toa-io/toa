# Migrating from 1.0.0-alpha.318

## A deploy is refused where the cluster does not hold a secret

`toa deploy` reads the secrets of the namespace it deploys into before it builds anything, and stops
where a key a workload would read is not there:

```
$ toa deploy production
Secrets are not deployed: toa-mongodb.default/username, toa-mongodb.default/password
```

What it requires is what `toa export secrets` lists, less the keys marked `(optional)`, plus the
`registry.credentials` secret where a context names one. See
[variables and secrets](/documentation/deployment.md#variables-and-secrets).

A deploy that was going to work works, and one that was going to stall on pods that cannot be
created now fails at the start instead. Two things change for what runs it:

- **A secret is in place before the command, not during it.** A pipeline that conceals a secret
  while the images build has to conceal it first.
- **Listing the secrets of the target namespace is required of whoever deploys.** Every Helm upgrade
  already lists them — that is where Helm keeps its release state — so a credential that could
  deploy can already read them; one that was given `get` on named secrets alone cannot.

`toa deploy --dry` reads no cluster, and neither does anything else that reads a context: `toa env`,
`toa export`, `toa build` and `toa push`.

## What to do

1. Deploy the secrets before running `toa deploy`, where something else in the pipeline was writing
   them.
2. Where a deploy runs under a credential of its own, let it list the secrets of the namespace it
   deploys into.

## A stream is answered what the method lists

`io:output` restricts each object a stream yields, as it restricts any other reply. A stream route
used to send every property of every object, whatever the method listed; one that declared no
`io:output` sent the whole stream too.

A method that declares no `io:output` now asks for none of the stream: the reply has no body, and
the stream is closed unread. See [I/O restrictions](/extensions/exposition/documentation/io.md#output).

## What to do

1. Give every method that answers a stream an `io:output`: the list of the properties a client may
   read, or `true` for a stream of primitives or of bytes.
