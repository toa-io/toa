# Migrating to 1.0.0-alpha.272

Domain events are published from a transactional outbox. Every component gains an `atom` aspect,
and the lock manager and rate meter move onto it out of the stash extension.

Three things every deployment does: point MongoDB at a replica set, declare `atomicity`, and stop
declaring a stash for `exposition.stash`.

Two things every component does: write its schemas as JSON Schema, and stop base64-encoding the
settings it passes through the environment.

## Events commit with the state that produced them

A stored component whose events something consumes writes each of them into `{collection}_outbox`
in the same transaction as the entity, and publishes it after the transaction rather than inside
the operation. An operation no longer waits for the broker, and a process that dies between the
write and the publish no longer loses the event.

The transaction is what makes this work, so the storage has to have one:

- **MongoDB on a replica set or a sharded cluster** commits the row with the entity.
- **A standalone `mongod`** cannot, says so at startup, and publishes inline as before. Nothing is
  lost that was not lost before, and nothing is recovered either.
- **`storages.sql` and `storages.null`** publish inline.

The outbox collection is created at boot, alongside the entity's, for a component whose events
something consumes. A component none of whose events are consumed takes no transaction and gets no
collection.

```yaml
# context.toa.yaml
outbox:
  interval: 5000      # the pump's cycle, in milliseconds
  batch: 200          # rows one read brings back
  retention: 86400    # seconds a published row is kept
```

Published rows expire by TTL. Unpublished rows carry no expiry field, so a row that never made it
out is never reaped: `db.<collection>_outbox.find({ published: false })` is what is stuck.

See [the outbox](/documentation/outbox.md).

## Only events that are consumed are published

An event is published where something consumes it: a receiver of another component of the context,
a realtime route, or an entry in the context's `events`. What nothing consumes gets no AMQP
exchange, no emitter and no outbox row.

Events consumed outside the context — a receiver in another deployment that names this one as its
`source` — are named in the context, or they stop arriving:

```yaml
# context.toa.yaml
events:
  - store.orders.created
```

Deployment states this per component in `TOA_EVENTS_<NS>_<NAME>`. A run without a deployment
publishes every event, as before.

## Atomicity is a context-level Redis

```yaml
# context.toa.yaml
atomicity:
  redis: redis://redis.example.com    # one address, or an odd number of them
  interval: 5000                      # how often a replica registers, milliseconds
```

It is system infrastructure rather than a per-component resource, so it is a plain value rather than
a Pointer, and it resolves to `TOA_ATOMICITY_REDIS`. Under `TOA_DEV=1` it is `redis://localhost`.

Without it a component still writes and publishes its events, but nothing recovers what failed to
publish, and metering and locking are refused. Throttling therefore needs it — see below.

## Every component has an atom

`context.atom` is there in every component, declared in no manifest.

```javascript
context.atom.slots(128)                       // [0, 2, 4, …] — or null, owning nothing
await context.atom.meter(['sam'], [1000])     // debt the replicas have run up, in milliseconds
await context.atom.lock('the ledger', routine)
```

The group is the component, so what one replica of it decides, all of them decide.
See [the connector](/connectors/atomicity).

## Metering and locking move off the stash

`context.stash.meter` and `context.stash.lock` are gone.

```javascript
await context.stash.meter(keys, deltas)   // →  await context.atom.meter(keys, deltas)
await context.stash.lock(key, routine)    // →  await context.atom.lock(key, routine)
```

Keys move with them. They were scoped by the stash client's `namespace:name:` prefix and are now
`meter:<group>:<key>` and `lock:<group>:<key>` in the atomicity Redis, so nothing carries over —
which costs nothing, as debt drains and a lock is held for seconds.

`atomicity.redis` takes an odd number of addresses, and they are **independent servers** rather than
the nodes of a cluster. The lock is written to all of them and a majority holding it is the lock;
partitioning and metering use the first, because each of them counts on a single key. An even number
is refused at export.

One address is the ordinary case, and what the stash always ran — nothing has ever pointed one at
more than one. There is then no majority to lose: a restart that drops the key, or a failover to a
replica that has not received it, can leave two holders. Entity writes do not rest on it — they have
`_version`.

A locked routine is given an `AbortSignal`. Extension can fail while it runs, and a routine that
does not check the signal can outlive its lock:

```javascript
await context.atom.lock('the ledger', async (signal) => {
  await something()

  if (signal.aborted) throw signal.error
})
```

## `exposition.stash` is `exposition.atom`

The component the gateway reconciles throttling through carries no extension and no Redis of its
own. Drop the entry that gave it one:

```yaml
# context.toa.yaml
stash:
  exposition.stash: redis://redis.example.com    # delete this
```

`io:throttle` now reconciles through `atomicity`. A gateway that cannot reach it keeps serving and
keeps throttling on what it alone has seen, and says so once a tick.

## The stash takes one address

Several addresses used to be the independent masters the lock manager needed. A cache is one Redis,
so the first is used and the rest are reported at startup. Nothing else about the extension changes.

## `event.changeset` is gone

An event carries `origin` and `state`, which is the same information twice over. A `condition` or a
`payload` that reads `event.changeset` reads `event.state` instead, or compares it with
`event.origin`.

## An assignment's event carries its pre-image

`event.origin` is the record as it was before the assignment, where it used to be absent. `created`
and `updated` fire exactly as they did. Only a storage that commits the row can produce it, so an
assignment on a standalone `mongod`, `storages.sql` or `storages.null` still emits none.

## `console.trace` writes a line

In `openspan`, `Console.trace(span)` is gone: `trace` is an ordinary log channel beside `debug` and
`info`, taking `(message, attributes)`, and a span is written with `Console.entry`. `context.logs.trace`
threw before and works now.

## Schemas are JSON Schema

COS is gone. Every schema is written as JSON Schema: `entity.schema`, `configuration.schema`, and
an operation's `input` and `output`, along with the `.cos.yaml` files an extension ships.

```yaml
# manifest.toa.yaml
entity:
  schema:
    authority*: string
    username*: string
```

```yaml
# manifest.toa.yaml
entity:
  schema:
    type: object
    properties:
      authority:
        type: string
      username:
        type: string
    required:
      - authority
      - username
```

The spellings that have no JSON Schema equivalent:

| COS | JSON Schema |
|---|---|
| `foo: string` | `properties: { foo: { type: string } }` |
| `foo*: string` | the same, and `foo` in `required` |
| `'foo?': string` | the same, and every *other* property in `required` |
| `foo: hello` | `{ type: string, default: hello }` |
| `foo: [1, 2]` | `{ type: number, enum: [1, 2] }` |
| `foo: [string]` | `{ type: array, items: { type: string } }` |
| `foo: <string>` | `{ type: object, patternProperties: { '^.+$': { type: string } } }` |
| `foo: ref:one#/foo` | `{ $ref: 'one#/foo' }` |
| `output: undefined`, `output: null` | `{}` |

The expansion was deterministic, so the conversion can be mechanical: `expand` from
`@toa.io/concise@1.0.0-alpha.254` — the last release that has it — reads a COS schema and returns
exactly what to write in its place.

`.cos.yaml` keeps its name. Schemas are still loaded by that suffix.

## Deployment settings are plain JSON

The environment variables that carry structured settings hold the JSON itself, where they used to
hold its base64. Anything that writes one by hand — a `.env`, a chart, a `docker run --env` — stops
encoding it:

```
TOA_STORAGES=eyJ0bXAiOnsicHJvdmlkZXIiOiJ0bXAifX0=
```

```
TOA_STORAGES={"tmp":{"provider":"tmp"}}
```

This covers `TOA_STORAGES`, `TOA_EXPOSITION`, `TOA_EXPOSITION_PROPERTIES`, `TOA_CONFIGURATION_*`,
`TOA_INTROSPECTION`, `TOA_REALTIME`, `TOA_TELEMETRY_LOGS`, `TOA_TELEMETRY_TRACES`,
`TOA_TELEMETRY_READY` and `TOA_AMQP_CONTEXT`. `toa export deployment` and `toa env` write the new
form, so a deployment that regenerates them needs nothing.

## Seven libraries are gone

`@toa.io/schema`, `@toa.io/mock`, `@toa.io/command`, `@toa.io/concise`, `@toa.io/filesystem`,
`@toa.io/tomato` and `@toa.io/yaml` are no longer published. What replaces each:

| Package | Instead |
|---|---|
| `@toa.io/schema` | `@toa.io/schemas` |
| `@toa.io/yaml` | `js-yaml` |
| `@toa.io/filesystem` | `node:fs/promises`, `fast-glob`, `find-up` |
| `@toa.io/command` | `promisify(exec)` from `node:child_process` |
| `@toa.io/concise` | JSON Schema, above |
| `@toa.io/mock`, `@toa.io/tomato` | nothing; they were test scaffolding |

Two YAML features go with `@toa.io/yaml`, both of which a manifest or a context could use:
`${{ VARIABLE }}` substituted an environment variable while the file was read, and `<assign` merged
in content from other files by glob and fragment. A file that uses either needs the value written
out. `1.0.0-alpha.254` is the last release of each package.

`directory.find`, which resolves a package directory, moves to `@toa.io/generic` as `find`.

## Storages takes DigitalOcean Spaces

```yaml
storages:
  photos:
    provider: spaces
    space: my-space
    region: fra1
```

`region` is the datacenter slug; the endpoint follows from it. `ACCESS_KEY_ID` and
`SECRET_ACCESS_KEY` are required — unlike `s3`, where they are optional and the AWS credential
chain answers for them. Keys come from the DigitalOcean control panel, under Spaces Object Storage,
on the Access Keys tab.

## The `mem` storage provider and the s3 `prefix` are gone

Neither did anything. `provider: mem` validated and then failed inside the factory, and `prefix` on
an `s3` storage was read nowhere. Both are now refused where the annotation is validated.

## What to do

1. Give every MongoDB behind a component with `events` a replica set, or accept inline publication.
2. Declare `atomicity.redis`.
3. Delete the `stash` entry for `exposition.stash`.
4. Read your operations for `context.stash.meter`, `context.stash.lock` and `event.changeset`.
5. Give the stash one address per selector.
6. Rewrite every schema as JSON Schema.
7. Stop base64-encoding the settings environment variables you write by hand.
8. Replace imports of the seven removed libraries, and write out any `${{ VARIABLE }}` or `<assign`.
9. Drop `provider: mem` storages and `prefix` from `s3` ones.
