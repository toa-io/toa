# Migrating from 1.0.0-alpha.310

## Stash and atomicity keys begin with the context

A stash key is `<context>:<namespace>:<component>:<key>`, where it was
`<namespace>:<component>:<key>`, and an atomicity key is `<context>:atom:<group>:…`, where it was
`atom:<group>:…`. Contexts sharing a Redis shared these keys, and no longer do. See
[deployment](/documentation/deployment.md#several-processes-of-one-context-on-shared-infrastructure).

What this means for what you run:

- **The stash starts empty.** What the previous release stored is where it was and is read by
  nothing. A value you cannot compute again is copied under the new key before the deploy, and
  what is left under the old ones expires as it was set to, or is deleted.
- **During the deploy, replicas of the two releases lock apart.** A lock held by one is not seen by
  the other, and partitions are handed out to each release as if the other were not there, so for
  as long as both run, two replicas may hold one lock or one slot. A routine that must never run
  twice at once is deployed through a [halt](/documentation/halt.md), or with the old replicas
  stopped before the new ones start.
- **Debt a meter ran up is forgotten**, and the group starts from none.

1. Copy what the stash holds and cannot be computed again under `<context>:` before deploying.
2. Deploy through a halt, or stopping the old replicas first, where a lock or a slot must never be
   held twice.
