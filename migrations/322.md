# Migrating from 1.0.0-alpha.322

## An assignment stores its moments as dates

An assignment — an operation of scope `changeset`, `assign` and `terminate` among them — wrote
what it set as it was given: `UPDATED` and `DELETED` as milliseconds, and a property of yours
declared with `format: epoch-millis` or `format: date-time` as the number or the string, where
every other write stores a date. Such a value sorts ahead of every date, is matched by no
criterion by time, and is skipped by a `ttl` index.

It is stored as a date now. `UPDATED` and `DELETED` are converted at start by the runtime's own
migration, `system:0003-assigned-moments`, which the release before this reads as it reads any
other date, so nothing stops for it.

A property of yours is converted by a migration of the component, as a property that takes the
format is — see [Moments](/documentation/component/declaration.md#moments):

```yaml
# migrations/0004-assigned-moments.yaml
- update:
    filter: { expires: { $type: number } }
    update:
      - $set: { expires: { $toDate: { $toLong: '$expires' } } }
```

## What to do

1. Add a migration converting the values an assignment wrote to a property of yours declared as
   a moment. `UPDATED` and `DELETED` need nothing.
