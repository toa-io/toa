# Migrating to 1.0.0-alpha.289

What the runtime was deployed with is no longer in a component's environment.

## `TOA_*` is not in `process.env`

Every `TOA_*` variable — the addresses and credentials of storages and brokers, the
`TOA_CONFIGURATION__<NAME>` a configuration secret refers to, `TOA_ENV`, `TOA_CONTEXT` — is
taken out of `process.env` before a component's module is imported. A component that read one
reads `context` instead: `context.env`, `context.name`, `context.configuration`. There was no
supported reason to read one.

A bash operation runs with the same environment, so a script sees no `TOA_*` either.

`echo(input)` of `@toa.io/generic` no longer substitutes `${NAME}` from the environment; pass
the variables.

## An image starts as root

The images `toa build` writes no longer switch to `node` before the command: the runtime starts
as root and drops to `node` itself, before it loads anything. A process that changed its uid is
non-dumpable, so its environment and memory under `/proc` are closed to the user it runs as —
which is what keeps the variables from a component's code by that road too.

A pod spec that sets `runAsUser` skips the drop, and the variables stay readable under `/proc`
for that user. One that sets `runAsNonRoot: true` refuses the container. One that drops
`CAP_SETUID` or `CAP_SETGID` fails the start: serving components as root is not a mode. The
chart Toa renders sets none of these.

What runs in the same process as the runtime is not kept from it by any of this: a heap
snapshot, an inspector session, a patched `Secret.prototype.unwrap` all reach what the runtime
holds. The environment is closed as a channel; the process is not a boundary.
