# Migrating to 1.0.0-alpha.280

Exposition's identity configuration names the authority it applies to, and a trusted issuer names
its audience.

## The principal names its authority

Basic credentials are unique per authority, and the principal was matched by username alone.
`identity.basic.principal` is an object with the authority the credentials are created in, and
`identity.federation.principal` carries `authority` beside `iss` and `sub`. The same username or
subject in another authority is ordinary credentials.

```yaml
# context.toa.yaml

configuration:
  identity.basic:
    principal: root
  identity.federation:
    principal:
      iss: https://accounts.google.com
      sub: 4218230498234
```

```yaml
# context.toa.yaml

configuration:
  identity.basic:
    principal:
      authority: example
      username: root
  identity.federation:
    principal:
      authority: example
      iss: https://accounts.google.com
      sub: 4218230498234
```

`authority` is the identifier from the `authorities` annotation, or the request host itself where
the host is not listed. A Context with the string form fails configuration validation.

## A trusted issuer requires `aud`

`identity.federation.trust[].aud` was optional and required for the Authorization Code Flow only.
It is required for every issuer, and a `Bearer` token is verified against it, against its `iss`, and
must carry `exp`. A token from a trusted issuer that was minted for another client is refused.

```yaml
# context.toa.yaml

configuration:
  identity.federation:
    trust:
      - iss: https://accounts.google.com
```

```yaml
# context.toa.yaml

configuration:
  identity.federation:
    trust:
      - iss: https://accounts.google.com
        aud: <GOOGLE_CLIENT_ID>
```

## The request authority is validated

The gateway answers `400 Bad Request` to a request whose `host` (or `:authority`) is not a host name
or a bracketed IPv6 literal, each with an optional port, and lowercases the value before the
`authorities` lookup. A value in the `authorities` annotation must be lowercase to match.

## Custom tokens are not refreshed

A custom token past the `refresh` period was reissued with the primary key, which dropped its
`permissions`. It is now accepted as issued until its `exp`, and is invalidated by deleting its
key, as documented. A client that read the `authorization` response header after using a custom
token no longer receives one.

## What to do

1. Write `identity.basic.principal` as `{ authority, username }` and add `authority` to
   `identity.federation.principal` in every Context and environment overlay.
2. Add `aud` to every `identity.federation.trust` entry.
3. Lowercase the values of the `authorities` annotation.
